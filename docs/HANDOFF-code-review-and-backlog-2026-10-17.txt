A1. BLOCKER — Ranking never moved onto SearchPlan
-------------------------------------------------
backend/main.py still does Layer 3 as:
  embed_texts -> deduplicate -> filter_by_relevance(focus, articles, embeddings)

There is no rerank.py. plan.must_terms and plan.synonyms are unused after ingest.
filter_by_relevance still tokenizes the raw focus string (extract_focus_terms).

must_terms/match_terms are used as OR ("any one term") in RSS / matches_plan.
That is recall-oriented and only safe if pre-filter + rerank exist. Without them,
"data centers and privacy" keeps privacy-only stories.

Code judo: one rank_articles(plan, articles, embeddings). Delete the dual brain.
Do not keep filter_by_relevance(focus, ...) as a parallel interpretation of the
same phrase. Fallback of rank_articles may call the old keyword+TF-IDF path on
the pre-filtered set (per spec), capped at RERANK_KEEP.

Related leftover: 422 empty-after-filter still hints only at NEWSAPI_KEY.
502 empty-ingest already lists skipped missing keys. Make those consistent.

A3. GDELT never joined the new contract
---------------------------------------
Other sources use get_json / empty-on-error. GDELT still raise_for_status, own
retry, process-global pacer, no quota.

Source timeout is 8s; ingest deadline 15s. GDELT still does ~5.5s pacing PLUS
5.5s+jitter retry on 429, on a shared httpx client whose timeout is also 8s.
Under load this source will log timeout/deadline more often than ok. The retry
is ornamental.

Judo: one HTTP helper, one timeout budget. If GDELT cannot retry inside 8s,
drop the retry or give it an explicit longer budget — do not leave both.


A4. RSS is still "fetch the world, keyword-OR later"
----------------------------------------------------
rss_source.fetch always hits ~25 feeds (world + US/tech + finance) then
keyword_hit on plan.match_terms. Spec said finance RSS always runs; that is a
lot of concurrent GETs on every climate/security briefing, sharing the 15s
deadline with the new APIs.

RSS parses dates with time.mktime (local TZ). Google News uses calendar.timegm.
Same feedparser struct_time, two clocks. Prefer timegm everywhere.

If rerank is not ready, RSS OR-matching on a single must_term (e.g. "privacy")
will dump noise into synthesis.


A5. Google News defaults to the US (product + quality)
------------------------------------------------------
google_news_source.fetch:
  cc = (plan.country or "US").upper()
Encoded in tests. "South Asian security" and "Red Sea shipping" get gl=US.
That fights the global-briefing product and the spec regression criteria.

Feed items already have <source url="https://www.reuters.com">; stored URL is
still news.google.com/rss/articles/.... Citations look like Google wrappers.
When URL-dedupe lands, Reuters-via-Google will not collapse with Reuters-via-RSS.

Judo: set gl/hl/ceid only when plan.country is set. Prefer publisher URL when
present; keep the Google link only as fallback (per spec §3.5).

B1. Next — high leverage, data we already have (Performance)
------------------------------------------------------------
1. Watchlist + "what changed since last brief"
   Highest linear value for a daily user. Archive is already keyed by focus.
   Mark new developments, dropped alerts, new contradictions.

2. Time-to-understand path (5 / 12 / 25 minutes)
   Same payload, different path: alerts -> top developments -> one contradiction
   -> readings. compactMode is only spacing; this is the job-to-be-done toggle.

3. Geographic coverage as a quality metric
   Promote Signals source mix: "62% US wires, 1 African desk."

4. Freshness and source depth (experienced as "this actually caught it")
   Ranking quality is backend; UI should show the score.

5. Repeatability
   Same focus tomorrow should be a comparable edition, not a slot machine.

6. Ask Atlas, grounded in THIS brief only
   Performance, not a delighter (every AI product has chat). The delighter is
   refusing to search when the brief does not cover the question. Do NOT let
   chat trigger a fresh search when the briefing is thin — that hides retrieval
   failure.

7. "Go deeper on this development"
   From a card, brief that thread using the headline as focus. Reuses POST /briefing.

8. Globe as a filter
   Click a region column; Story/Signals filter to those developments. Mapping
   already exists; globe is decorative after generate.


B2. Later — real expansion / unique Atlas delighters
----------------------------------------------------
Narrative geography:
- Framing compass: Western wires vs regional desks vs state-adjacent, using the
  RSS mix that already exists (BBC, Al Jazeera, The Hindu, AllAfrica, NYT, Guardian).
- Contradiction as the hero: "split in the story" — two outlet clusters, one
  factual delta. Zero contradictions = "unusually aligned coverage," not an empty card.
- Silence detector: this focus went quiet vs last week (archive + source mix).
- Delta globe: yesterday vs today region columns grow/shrink.
- Campaign / flow map on Story: linked second-order effects (Red Sea -> Suez ->
  insurers -> food prices) using existing branch/tension links.

Time-constrained reader:
- Sequenced reading pack: "read this first, this is the dissent, skip the third
  if you only have 5 minutes." RecommendedReading.why already exists.
- Seminar mode: three discussion questions extracted from THIS brief's
  contradictions/tensions. Profile already has fieldOfStudy. Extractive only.
- Devil's-advocate regen: same articles, steelman the underweighted account.
  Labeled as a lens, not a new truth. Pairs with archive compare.
- Lens toggle (analyst / investor / policy / journalist): SAME article set,
  different emphasis. Citations stay identical. Personas must not change which
  facts you see.

Trust:
- Citation hover = original snippet Atlas used. Cheap if snippets are persisted.
  Delighter that becomes must-be.
- "What would change this take": missing evidence ("no regulator filing,"
  "no Iranian state-media account").
- Outlet cluster graph on Signals.

Habit / object:
- Morning edition: 3 saved foci, one "plate," local timezone already stored.
  Needs a warm backend or honest "edition ready when the server wakes."
- 90-second spoken brief of alerts + top development (reverse for citation-skimmers).
- Shareable edition link (read-only URL). Share was dropped in the overhaul
  because there is no server store. This is how the product spreads.
- Follow an actor across the archive ("Houthis", "Fed").
- Alert only on threshold (browser notify for critical/high or a new contradiction).
- Accounts/sync: only if share or multi-device is real. Do not add auth for
  Settings name/email fields.
- Longitudinal tensions: actor-pairs across archived briefs (secondary to deltas).
- Paid/reliable compute: Render cold start (~1 min) and GDELT shared-IP 429s
  are bigger UX wins than another news API.
